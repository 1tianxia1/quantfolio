## 0. 项目信息

| 项 | 内容 |
|---|---|
| 项目名称 | `quantfolio` |
| 项目定位 | 面向 A 股个人投资者的「持仓管理 + 智能选股」一体化本地全栈平台 |
| 文档语言 | 中文 |
| 前端技术栈 | Vite + React + MUI + Tailwind CSS |
| 后端技术栈 | Node.js + Express + SQLite（better-sqlite3） |
| 认证方案 | JWT + bcrypt |
| 数据源 | 通达信真实 A 股行情。工程上抽象 `DataProvider` 适配层：开发期由主理人通过通达信连接器拉取真实行情落库作为种子数据；运行期后端读本地库，并预留 HTTP 数据源适配位 |
| AI 引擎 | 智谱 GLM-4-flash（真实调用），后端统一封装，API Key 走 `.env` |
| 交付形态 | 本地可运行全栈项目 + 一键启动脚本 |

### 0.1 原始需求复述

> 「股票基金网址账户密码注册登录，需要数据库存数据，需要 AI 分析。1：个人投资组合再平衡仪表盘模块，2：早盘选股模块 3：尾盘选股器：量化指标帮你快速筛选股票」

即：建设一个带**账号体系 + 持久化数据库 + AI 分析能力**的股票/基金投资网站，包含三大核心功能模块——投资组合再平衡仪表盘、早盘选股、尾盘量化选股器。

## 1. 产品目标

| # | 目标 | 说明 | 衡量口径 |
|---|---|---|---|
| G1 | **让个人投资者看清自己的组合** | 用户录入持仓后，一屏看到总资产、盈亏、资产配置偏离，并拿到可执行的「买X股/卖Y股」调仓建议 | 用户录入持仓后 ≤3 次点击即可获得具体调仓数量建议 |
| G2 | **把「怎么选股」从主观感觉变成可复现的量化流程** | 早盘（消息面/情绪面）与尾盘（技术面/估值面）两套场景化选股器，条件可配置、可保存、结果可复现 | 用户可保存并一键复用自定义策略；同一策略同一数据快照下结果一致 |
| G3 | **用 AI 把量化结果翻译成人话** | 对持仓组合、早盘结果、尾盘 Top 标的分别给出 GLM 生成的诊断/点评/逻辑解读，降低理解门槛 | 三大模块均有 AI 输出入口，单次响应 ≤15s |

**目标用户**：有 A 股实盘持仓、会看基本技术指标、但缺乏系统化组合管理与批量筛选工具的个人投资者（散户/半专业投资者）。

**非目标（本期不做）**：实盘下单交易、券商账户对接、实时 Level-2 逐笔行情推送、社区/社交功能、移动端 App。

## 2. 用户故事

### 2.1 账号体系

| # | 用户故事 |
|---|---|
| U-A1 | 作为**新用户**，我希望用邮箱+密码快速注册并登录，以便我的持仓和策略被安全地保存在我自己的账号下 |
| U-A2 | 作为**未登录访客**，我希望能先看到演示数据体验产品功能，以便我在注册前判断这个工具是否对我有用 |
| U-A3 | 作为**已登录用户**，我希望我的持仓、目标配置、自定义策略只有我能看到，以便保护我的隐私资产信息 |

### 2.2 模块一：个人投资组合再平衡仪表盘

| # | 用户故事 |
|---|---|
| U-P1 | 作为**持有多只股票和基金的投资者**，我希望录入并管理我的持仓（代码、名称、数量、成本价、资产类别），以便系统能基于真实行情算出我的实时市值和盈亏 |
| U-P2 | 作为**关注资产配置的投资者**，我希望设定目标配置比例（如股票60%/基金30%/现金10%）并看到当前配置与目标的偏离，以便我知道自己是不是「跑偏」了 |
| U-P3 | 作为**准备调仓的投资者**，我希望系统直接告诉我「买入X股/卖出Y股」的具体数量，并且只在偏离超过我设定的阈值时才提示我，以便我避免无意义的频繁交易 |
| U-P4 | 作为**不确定自己组合有没有风险的投资者**，我希望 AI 帮我诊断持仓集中度、行业分布和潜在风险，以便我用大白话理解自己的问题 |

### 2.3 模块二：早盘选股模块

| # | 用户故事 |
|---|---|
| U-M1 | 作为**开盘前做功课的投资者**，我希望看到一份基于昨日涨跌幅、量比、换手率、竞价表现、连板、热点板块、资金流向筛选出的「今日机会股」列表，以便我快速锁定关注池 |
| U-M2 | 作为**有自己选股偏好的投资者**，我希望自定义早盘筛选条件并保存成策略，以便每天开盘前一键跑出我自己的名单 |
| U-M3 | 作为**看不懂为什么这票入选的投资者**，我希望每只票旁边有入选理由和综合评分，并且 AI 给出当日整体市场情绪判断，以便我判断今天该激进还是保守 |

### 2.4 模块三：尾盘选股器（量化指标筛选）

| # | 用户故事 |
|---|---|
| U-C1 | 作为**做尾盘布局的投资者**，我希望用 MACD/RSI/KDJ/均线多头排列/放量倍数/换手率/PE/市值/涨跌幅等指标做多条件 AND 组合筛选，以便精确圈定符合我技术逻辑的标的 |
| U-C2 | 作为**需要复用策略的投资者**，我希望把筛选方案保存为「我的策略」并支持一键复用和导出 CSV，以便我持续跟踪同一套逻辑的表现 |
| U-C3 | 作为**面对一堆筛选结果的投资者**，我希望结果表格展示命中的指标标签和 0-100 综合评分并可排序，同时 AI 对 Top 标的解释量化逻辑，以便我从名单里挑出最值得看的几只 |

## 3. 需求池

> 优先级定义：**P0 = 本期必须交付**；**P1 = 应该有，时间允许则做**；**P2 = 锦上添花，可延后**。
> 下列需求已按「可直接转换为 API 与数据表」的粒度书写，字段名为建议命名，架构师可调整。

### 3.1 账号体系（贯穿）

| ID | 需求 | 关键字段 / 规则 | 优先级 |
|---|---|---|---|
| A-01 | 用户注册 | `username`（唯一）、`email`（唯一、格式校验）、`password`（≥8位，bcrypt salt rounds=10 加密存储）、`created_at`。禁止明文存储 | P0 |
| A-02 | 用户登录 | 支持 `email` 或 `username` + 密码登录，成功返回 JWT（`exp` 建议 7天），响应体不含密码哈希 | P0 |
| A-03 | 登出 | 前端清除 token；后端提供 `/auth/logout` 语义接口 | P0 |
| A-04 | 获取当前用户信息 | 依据 JWT 返回 `id/username/email/created_at` | P0 |
| A-05 | JWT 鉴权中间件 | 所有个人数据接口（持仓、目标配置、策略）必须校验 JWT，未通过返回 401 | P0 |
| A-06 | 用户数据隔离 | `portfolios`、`holdings`、`target_allocations`、`strategies`、`ai_reports` 等表均带 `user_id` 外键，查询强制按 `user_id` 过滤 | P0 |
| A-07 | 游客演示模式 | 未登录访问三大模块时，展示只读演示数据（内置 demo 持仓 + 全市场选股结果），所有「保存/编辑」操作引导至登录 | P0 |
| A-08 | 修改密码 | 校验旧密码 → 更新新密码哈希 | P1 |
| A-09 | 前端路由守卫 | 未登录访问 `/portfolio/edit` 等写操作页面自动跳转登录页，登录后回跳原地址 | P1 |
| A-10 | 密码找回（邮箱验证码） | — | P2 |

| D-04 | 技术指标表 `tech_indicators`（或视图/实时计算） | `code`、`trade_date`、`ma5`、`ma10`、`ma20`、`ma60`、`macd_dif`、`macd_dea`、`macd_bar`、`rsi6`、`rsi12`、`rsi24`、`kdj_k`、`kdj_d`、`kdj_j`、`vol_ma5`、`vol_ratio_5`（当日量/5日均量） | P0 |
| D-05 | 种子数据导入脚本 | 提供 `npm run seed`，将主理人通过通达信连接器导出的真实 A 股行情（建议覆盖 ≥300 只标的、≥60 个交易日）写入 SQLite | P0 |
| D-06 | 资金流向数据 `money_flow` | `code`、`trade_date`、`main_net_inflow`（主力净流入，万元）、`net_inflow_3d`、`net_inflow_5d` | P0 |
| D-07 | 集合竞价数据 `auction_data` | `code`、`trade_date`、`auction_price`、`auction_pct`（竞价涨幅）、`auction_volume`、`auction_amount`、`auction_vol_ratio`（竞价量占昨日成交量比） | P0 |
| D-08 | 连板/涨停记录 `limit_records` | `code`、`trade_date`、`limit_type`（涨停/跌停/炸板）、`limit_up_streak`（连板数）、`first_limit_time` | P0 |
| D-09 | 热点板块表 `hot_sectors` | `sector_name`、`trade_date`、`sector_pct_chg`、`hot_rank`、`leading_stock` | P1 |

### 3.3 模块一：个人投资组合再平衡仪表盘

| ID | 需求 | 关键字段 / 规则 | 优先级 |
|---|---|---|---|
| P-01 | 持仓 CRUD | `holdings` 表：`id`、`user_id`、`code`、`name`、`asset_class`（stock/fund/cash/bond/other）、`quantity`（股/份）、`cost_price`、`created_at`、`updated_at`。支持新增/编辑/删除/批量列表 | P0 |
| P-02 | 现金资产录入 | `asset_class=cash` 时允许无 `code`，直接录入金额（`quantity`=金额，`cost_price`=1） | P0 |
| P-03 | 持仓实时估值 | 后端按 `code` 从 `DataProvider` 取最新 `close` 作为现价，计算：`market_value = quantity × current_price`；`cost_amount = quantity × cost_price`；`profit = market_value - cost_amount`；`profit_rate = profit / cost_amount` | P0 |
| P-04 | 仪表盘汇总卡片 | 展示：总资产（Σ market_value）、总成本、总盈亏、总盈亏率、当日盈亏（Σ quantity × (close - pre_close)）、持仓标的数 | P0 |
| P-05 | 持仓明细表 | 列：代码、名称、资产类别、持仓数量、成本价、现价、市值、盈亏额、盈亏率、当前占比(%)、目标占比(%)、偏离度、操作。支持按任意列排序 | P0 |
| P-06 | 目标配置管理 | `target_allocations` 表：`id`、`user_id`、`dimension`（asset_class / industry / code 三选一）、`target_key`（如 `stock` / `白酒` / `600519`）、`target_pct`（0-100）。同一 dimension 下 Σtarget_pct 必须 = 100，否则保存报错 | P0 |
| P-07 | 资产配置可视化 | 环形图（当前配置）+ 环形图或叠加条形（目标配置）对比；支持切换维度：资产类别 / 行业 / 个股 | P0 |
| P-08 | 偏离度计算 | `deviation_pct = current_pct - target_pct`（绝对百分点）。同时输出相对偏离 `deviation_ratio = (current_pct - target_pct) / target_pct` | P0 |
| P-09 | 再平衡阈值设置 | 用户可设 `rebalance_threshold`（默认 5，单位：百分点），仅当 \|deviation_pct\| ≥ 阈值时才生成调仓建议并高亮 | P0 |
| P-10 | **再平衡调仓建议** | 对每个超阈值标的输出：`action`（BUY/SELL/HOLD）、`target_value`（= 总资产 × target_pct）、`diff_value`（= target_value - market_value）、`suggest_shares`（= \|diff_value\| / current_price，**按 A 股 100 股一手向下取整**，基金按份取整）、`suggest_amount`。列表按 \|diff_value\| 降序 | P0 |
| P-11 | 调仓建议汇总校验 | 展示调仓后预计各项占比，并提示「买入总额 vs 卖出总额」是否平衡，现金不足时给出警示文案 | P1 |
| P-12 | **AI 持仓诊断** | 调用 GLM-4-flash。入参：持仓明细（代码/名称/行业/市值/占比/盈亏率）、行业分布、集中度指标（前三大持仓占比 CR3、HHI）、当前 vs 目标偏离。输出结构化：①集中度评价 ②行业分布评价 ③风险提示（≥2条）④调仓建议（人话版，≥3条）。结果写入 `ai_reports` 表缓存，同一用户同一交易日复用 | P0 |
| P-13 | 持仓导入 | 支持 CSV 批量导入持仓（模板：代码,名称,资产类别,数量,成本价） | P1 |
| P-14 | 组合历史净值曲线 | 基于持仓 + 历史日线回溯组合净值走势图 | P1 |
| P-15 | 多组合管理 | 一个用户可建多个 portfolio（如「主账户」「打新账户」） | P2 |
| P-16 | 组合风险指标 | 波动率、最大回撤、夏普比率 | P2 |

### 3.4 模块二：早盘选股模块

| ID | 需求 | 关键字段 / 规则 | 优先级 |
|---|---|---|---|
| M-01 | **早盘筛选维度定义** | 支持以下 7 类条件（每类可开关、可设阈值）：<br>① `prev_pct_chg` 昨日涨跌幅区间（%）<br>② `volume_ratio` 量比 ≥ X（默认 1.5）<br>③ `turnover_rate` 换手率区间（%，默认 3~15）<br>④ `auction_pct` 竞价涨幅区间（%）+ `auction_vol_ratio` 竞价量比 ≥ X<br>⑤ `limit_up_streak` 连板数区间（0=不限，1=首板，≥2=连板）<br>⑥ `sector` 所属热点板块（多选，或「仅热点前N板块」）<br>⑦ `net_inflow_3d` 近3日主力净流入 ≥ X 万元 | P0 |
| M-02 | 通用过滤开关 | 排除 ST/*ST、排除次新股（上市 < 60 日）、排除停牌、市值区间（亿元）、价格区间（元） | P0 |
| M-03 | **早盘综合评分模型** | 0-100 分加权。建议权重：量比 20%、竞价表现 20%、资金流向 20%、连板/涨停强度 15%、换手率 15%、板块热度 10%。各因子先做分位归一化再加权，输出 `score` 与各因子分项得分 `score_detail` | P0 |
| M-04 | **入选理由生成** | 对每只票输出理由标签数组，如：`["量比2.3倍放量", "竞价高开3.2%", "3日主力净流入5800万", "二连板", "属热点板块：AI算力"]`。由规则引擎生成，非 AI 生成 | P0 |
| M-05 | 早盘结果列表 | 列：排名、代码、名称、昨收、昨日涨跌幅、量比、换手率、竞价涨幅、连板、所属板块、3日主力净流入、综合评分、入选理由标签。默认按 score 降序，Top 50 | P0 |
| M-06 | 自定义策略保存 | `strategies` 表：`id`、`user_id`、`name`、`type`（`morning` / `closing`）、`conditions`（JSON）、`created_at`、`updated_at`。支持新增/重命名/删除/一键应用 | P0 |
| M-07 | 预置策略模板 | 内置 ≥3 套：「打板情绪流」「温和放量+资金流入」「热点板块跟随」，游客也可用 | P0 |
| M-08 | **AI 早盘点评** | 调用 GLM-4-flash。入参：当日选股结果 Top10 摘要、涨停家数、板块热度排行、大盘昨日涨跌幅。输出：①当日市场情绪判断（乐观/中性/谨慎 + 理由）②板块主线判断 ③操作提示（仓位建议、注意事项 ≥2条）。按交易日缓存 | P0 |
| M-09 | 结果导出 CSV | — | P1 |
| M-10 | 自选股关注 | 从早盘结果一键加入自选池 `watchlist` | P1 |
| M-11 | 选股结果历史回溯 | 保存每日选股快照，展示 T+1 / T+3 涨跌表现验证策略有效性 | P2 |

### 3.5 模块三：尾盘选股器（量化指标筛选）

| ID | 需求 | 关键字段 / 规则 | 优先级 |
|---|---|---|---|
| C-01 | **MACD 筛选** | 条件项：`macd_status` ∈ {金叉(DIF 上穿 DEA)、死叉、DIF>0、MACD柱由负转正}。基于 `macd_dif/macd_dea/macd_bar` 及前一交易日值判定 | P0 |
| C-02 | **RSI 筛选** | 选择周期（RSI6 / RSI12 / RSI24）+ 数值区间。快捷预设：超卖(<30)、正常(30~70)、超买(>70) | P0 |
| C-03 | **KDJ 筛选** | 条件项：`kdj_status` ∈ {金叉(K 上穿 D)、死叉、J<0 超卖、J>100 超买}；亦支持 K/D/J 数值区间 | P0 |
| C-04 | **均线多头排列** | 条件项：`ma_pattern` ∈ {多头排列(MA5>MA10>MA20)、空头排列、股价站上MA20、股价上穿MA5} | P0 |
| C-05 | **成交量放大倍数** | `vol_ratio_5 = volume / vol_ma5`，支持设定 ≥ X（默认 1.5），亦支持区间 | P0 |
| C-06 | **换手率区间** | `turnover_rate` 下限/上限（%） | P0 |
| C-07 | **市盈率 PE 区间** | `pe_ttm` 下限/上限，支持勾选「剔除负 PE（亏损股）」 | P0 |

## 5. 待确认问题（不阻塞开发，均已给出默认假设）

| # | 问题 | 默认假设（按此实现） |
|---|---|---|
| Q1 | 基金（场外）没有实时行情，如何估值？ | 场外基金按 `securities.type='fund'` 存最新净值到 `daily_quotes.close`，由种子数据提供；无数据时以成本价估值并在 UI 标注「净值待更新」 |
| Q2 | 「现价」用什么？种子数据是日线，无盘中实时价 | 统一使用**最新交易日收盘价**作为现价；UI 明确标注数据日期（如「行情截至 2026-08-07 收盘」） |
| Q3 | 早盘竞价数据在真实场景需 9:25 后才有，种子数据如何模拟？ | 使用历史交易日的真实开盘数据反推竞价字段（`auction_price=open`），落到 `auction_data` 表；产品逻辑不变 |
| Q4 | 再平衡建议中现金不足以买入时怎么办？ | 仍给出理论建议数量，同时在汇总区提示「所需资金 ¥X，超出可用现金 ¥Y」，不自动缩减 |
| Q5 | 目标配置支持三种维度（资产类别/行业/个股），是否允许同时启用？ | 同一时刻**只启用一种维度**，用户在仪表盘切换；三套目标配置数据可并存 |
| Q6 | 综合评分的权重是否让用户可调？ | 本期**权重固定**（写在配置文件中，架构师可配），不开放给用户；列入 P2 |
| Q7 | 全市场标的量级？种子数据覆盖多少只？ | 假设种子数据覆盖 300~800 只主流标的、近 60 个交易日。UI 文案不写死「全市场 5120 只」，改为读实际入库数量 |
| Q8 | 港股/美股/可转债是否支持？ | 本期**仅 A 股 + 场内外基金**；`securities.market` 字段预留扩展 |
| Q9 | 是否需要「持仓交易流水」（分批建仓/加减仓记录）？ | 本期只存**当前持仓快照**（数量+摊薄成本价），不做流水。流水列入 P2 |
| Q10 | AI 输出是否需要严格结构化 JSON？ | Prompt 要求 GLM 返回**固定小节标题的 Markdown**，后端按小节切分渲染；不强制 JSON，避免解析失败 |
| Q11 | 游客演示数据从哪来？ | 内置一份固定的 demo 持仓（8~10 只标的），`user_id = null`，只读；选股模块游客可用预置策略跑真实种子数据 |
| Q12 | 一键启动脚本的目标平台？ | 主交付 Windows `start.bat`，同时提供 `start.sh` 兼容 macOS/Linux |
| Q13 | 涨跌停价格、停牌标记是否需要？ | 种子数据若含则入库并在 UI 展示标记；无则跳过，不阻塞 |
