## 一、研究背景与产品上下文

QuantFolio 当前包含三大核心模块，目标用户为 **A 股个人投资者**：

| 模块 | 核心场景 | 关键任务 | 已暴露的设计假设 / 风险点 |
|---|---|---|---|
| **组合仪表盘** | 持仓估值、目标配置、再平衡建议、AI 诊断 | 查看持仓 → 理解再平衡建议 → 执行/模拟调仓 | AI 诊断的可信度与"建议→行动"的转化路径未经验证 |
| **早盘选股** | 9:25–9:30 竞价后短线选股（七步法漏斗） | 跑七步法 → 看竞价榜 → 读 AI 点评 → 决策 | **已知限制**：第 4 步要求「流通市值 <10 亿」，种子池小盘标的极少，常出现"结果为空"（README U1） |
| **尾盘选股器** | 14:30 后尾盘布局（五步法漏斗） | 跑五步法 → 看命中标的 → 读 AI 解读 → 决策 | 漏斗每步淘汰原因是否让用户"看得懂、学得会"待验证 |

**已存在但未经用户验证的设计决策（须作为研究假设重点检验）：**
- H1：深色优先的"金融终端"美学符合多数投资者长时间看盘习惯；
- H2：游客演示模式（屏蔽所有保存/编辑）不会显著损害新用户的价值感知；
- H3：BYOK 自行配置 AI 模型（选厂商/填 Key）对非技术型散户门槛可控；
- H4：红涨绿跌、等宽数字、分层表面等设计 Token 提升信息辨识效率；
- H5（重点）：早盘七步法"结果为空"是当前最突出的流失与挫败点。

> 研究方法论原则：**先建立研究问题，再选方法**。本计划所有方法均倒推自第 2 节的研究问题。

## 二、研究问题（Research Questions）

### Phase 1 · 探索性（Generative）—— 回答"用户是谁、要什么、痛在哪"
- **RQ1（目标与心智模型）**：A 股个人投资者在"组合管理 + 选股"全链路上的核心目标、决策流程与心智模型是什么？
- **RQ2（痛点地图）**：用户在三大模块各自遇到的**最大痛点、卡点与流失点**分布在哪？
- **RQ3（AI 信任）**：用户对"AI 诊断 / 早盘点评 / 尾盘解读"的信任来源、使用动机与能力边界期望是什么？
- **RQ4（群体差异）**：新手 / 进阶 / 资深，以及不同年龄（尤其 ≥51 岁银发组）在需求与障碍上有何系统性差异？

### Phase 2 · 验证性（Evaluative）—— 回答"方案好不好用、达不达标"
- **RQ5（设计有效性）**：新 UI 设计方案（深色优先 / 一致性组件 / 统一原语）相较现状，在任务完成率、效率、满意度上是否显著提升？
- **RQ6（可用性达标）**：三大模块核心任务（再平衡操作、早盘七步法、尾盘五步法）的可用性是否达标（完成率 ≥80%、SUS ≥68）？
- **RQ7（痛点验证）**：H5（早盘七步法结果为空）的实际发生频率、用户应对行为与挫败强度是否被高估/低估？
- **RQ8（包容性）**：深色主题对银发 / 低视力用户的可访问性是否达到 WCAG 2.1 AA？

## 三、研究方法论总览

采用 **混合方法（Mixed Methods）Sequential Explanatory 设计**：Phase 1 定性探索产出假设与用户细分 → 指导 Phase 2 的验证方案与问卷题项；Phase 2 定量验证再反哺并修正 Phase 1 的发现。

| 维度 | Phase 1（探索） | Phase 2（验证） |
|---|---|---|
| 性质 | 定性主导 | 定性 + 定量混合 |
| 方法 | 深度访谈（半结构）、情境调查（屏幕录制） | 可用性测试、问卷调查、行为数据分析、可访问性走查 |
| 目的 | 发现需求 / 痛点 / 细分 | 验证可用性 / 设计有效性 / 痛点频率 |
| 样本 | 12–15 人 | 可用性 10 人 + 问卷 ≥200 人 + 银发专项 5 人 |
| 输出 | Persona、痛点地图、研究假设 | 可用性指标、SUS/NPS、痛点频率、改版前后对比 |

**为何这样选**：探索阶段若直接上问卷，会把研究者的假设强加给用户；验证阶段若只做访谈，无法量化"到底多少用户受影响"。定性与定量互补、互为三角验证，结论才可靠。

## 四、Phase 1 探索性研究设计

### 4.1 方法一：深度访谈（In-depth Interview）
- **形式**：1 对 1 线上/线下，60 分钟，半结构化（提纲见工具包）。
- **样本量**：**n = 12–15**。依据：Guest et al. (2006) 实证显示约 12 次访谈即可覆盖 ~90% 主题；对异质人群（经验 × 年龄跨度大）建议 15 人以保饱和。
- **内容主线**：看盘习惯 → 组合管理场景 → 早/尾盘选股场景 → 对 AI 分析的信任 → 对游客模式/BYOK/深色美学的感知。
- **记录**：录音 + 转录 + 研究者笔记；事后 24h 内补写反思笔记（减少回忆偏差）。

### 4.2 方法二：情境调查（Contextual Inquiry，可选但推荐）
- **形式**：邀请 5 名典型用户在**自己日常看盘环境**中演示"今天是怎么选股/管仓的"，研究者旁观察并记录环境干扰、多屏习惯、信息源切换。
- **目的**：补足访谈中用户"理想化描述"与"真实行为"的差距（如是否同时开多个软件对照）。
- **样本量**：n = 5（从访谈样本中选取行为典型者）。

### 4.3 招募标准与分层（探索阶段）
必须满足全部基础条件，再按配额分层抽样：
- **基础门槛**：近 3 个月有 A 股实际交易；使用过至少一类炒股软件（同花顺/东方财富/券商 App 等）。
- **分层抽样维度**：
  - 经验：新手（<1 年）30% / 进阶（1–5 年）40% / 资深（>5 年）30%
  - 年龄：≤30 岁 / 31–50 岁 / **≥51 岁（银发组，必须 ≥3 人，用于检验 H1/H4 的可访问性风险）**
  - 性别：男女尽量均衡（金融类研究常见男性偏差，需主动校正）
  - 资金规模：小户（<10 万）/ 中户（10–50 万）/ 大户（>50 万）各占一定比例

## 五、Phase 2 验证性研究设计

### 5.1 可用性测试（Usability Testing，出声思考法）
- **样本量**：**主样本 n = 10**（完成三大模块全部核心任务，轮换顺序抵消学习效应）；**银发专项 n = 5**（≥55 岁，单独测试深色主题可读性）。
- **依据**：Nielsen (2000) 表明 5 人可发现约 80% 可用性问题；取 10 人可在保留问题发现力的同时获得较稳定的完成率/SUS 指标。
- **任务**：见工具包"可用性任务场景"（组合再平衡、早盘七步法、尾盘五步法、BYOK 模型设置）。
- **指标**：任务完成率、时长、错误数、求助次数、SUS、前后情绪评分。

### 5.2 问卷调查（Survey，量化）
- **样本量**：**n ≥ 200**（线上问卷，95% 置信水平、误差 ±7%；若需 ±5% 则扩至 385）。
- **量表**：模块使用频率、SUS（系统可用性量表 10 题）、NPS（净推荐值）、AI 信任量表、可访问性自评、人口统计。
- **发放**：炒股社区（雪球/韭研/同花顺圈子）、券商客户经理引荐、产品内邀请（若有试用用户）。

### 5.3 行为数据分析（Behavioral Analytics）
- **前提**：需有可埋点的试用版/线上版。若暂无，则本项为"待上线后补做"的后续研究。
- **关注**：三大模块任务漏斗完成率、功能使用率、停留时长、早盘七步法"空结果"实际触发率（直接验证 H5/RQ7）。

### 5.4 可访问性评估（Accessibility Audit）
- **方法**：WCAG 2.1 AA 标准走查（对比度、焦点可见、触控目标 ≥44px、prefers-reduced-motion）+ 银发专项可用性测试。
- **目标**：直接回答 RQ8，验证 H1/H4 对弱势群体的风险。

## 六、参与者招募与运营计划

| 项 | 说明 |
|---|---|
| 招募渠道 | 炒股社区招募帖、券商客户经理引荐、朋友圈/社群转发、产品内邀请（若有） |

## 九、预期产出物（Deliverables）

1. **用户画像 Persona（2–3 个）**：基于实证数据，含目标、痛点、行为、场景引用原话。
2. **用户旅程地图（全链路）**：触点、痛点、情绪曲线、优化机会。
3. **痛点优先级矩阵**：影响 × 频率二维排序，指导改版优先级。
4. **可用性测试报告**：任务完成率、时长、错误、SUS、典型问题录屏片段。
5. **问卷分析报告**：使用频率、SUS、NPS、AI 信任、可访问性分项。
6. **研究仓库（Research Repository）**：访谈转录、编码本、原始数据、洞察归档，形成机构知识资产。

## 十、成功度量指标（验收标准）

| 类别 | 指标 | 目标值 |
|---|---|---|
| 任务可用性 | 三大模块核心任务完成率 | ≥ 80% |
| 系统可用性 | SUS 总分 | ≥ 68（行业平均线） |
| 用户口碑 | NPS | 由负转零以上（基线待测） |
| 满意度 | 整体满意度（5 分制） | ≥ 4.2 |
| 痛点验证 | 早盘七步法"空结果"实际触发率 | 量化并给出整改优先级 |
| 包容性 | WCAG 2.1 AA 达标项 | 银发组关键路径 100% 达标 |

## 十一、偏差缓解与质量保障

- **三角验证**：访谈 + 可用性 + 问卷 +（若有）行为数据，四类来源交叉印证，避免单一方法误导。
- **避免确认偏差**：研究问题来自产品假设（H1–H5），但分析时主动寻找"反证"，报告须包含"未证实/被推翻的假设"。
- **分析者三角**：质性编码由 2 名研究员独立编码后比对，一致性不足则协商/引入第三人。
- **样本代表性**：强制银发组与性别均衡，防止"年轻男性程序员视角"替代真实用户。
- **可重复性**：全部脚本、筛选条件、统计代码入研究仓库，确保结果可追溯。

---

## 十二、伦理与合规

- **知情同意**：录音/录屏/问卷前明确告知用途、匿名化方式与退出权。
- **敏感数据最小化**：不收集账户、持仓明细、身份证等；金融场景尤须谨慎。
- **匿名化与存储**：数据脱敏后存于受控目录，访问受限；报告仅用化名/编号引用。
- **合规提示**：研究涉及投资类工具，所有产出须保留"量化模型输出不构成投资建议"的免责声明，不在研究中提供具体买卖建议。

## 十三、待确认事项（执行前需你拍板）

1. **预算与排期**：8 周 / 6 周哪个更贴合？激励预算是否到位？
2. **招募主导方**：由你方招募还是我协助设计招募物料并对接渠道？
3. **行为数据可用性**：当前是否有可埋点的试用环境？若无，Phase 2 行为分析改为上线后补做。
4. **改版对比基线**：新 UI 方案是否已有"旧版"可对比？若有，Phase 2 可做前后测配对检验，结论更强。
5. **银发样本可行性**：≥55 岁样本 5 人是否可招募到？这是 H1/H4/RQ8 的关键。
